# 其余模块架构与逻辑审查（2026-09-22）

结论：行情、感官输入、神经传播、固定动作解码、风控和执行的基本分层可以保留。主要缺陷集中在模块之间的状态约定，以及辅助工具中重复实现的账务逻辑。本次没有改变神经网络计算规则，也没有增加策略或隐藏动作选择。

## 检查范围

| 部分 | 审查重点与结果 |
| --- | --- |
| 账本与风控 | 下单意图、尝试次数、拒绝和结算边界；加强统一状态校验和已记录计划的一致性 |
| Coinbase / OKX 接口 | 身份绑定、发送前检查、未知结果与重试隔离；统一提交计数和未发送意图的拒绝逻辑 |

| 审计与账本合并工具 | 订单身份、买卖方向、手续费、账户隔离、并发快照和未完成迁移；修复重复计算及状态绕过 |

## 已确认并修复

### 账本合并的重复算法

合并工具在调用正确的净变动计算后，又运行了一段旧算法，重复读取余额并覆盖结果。旧算法把所有成交金额都当作支出，卖出时还会算错基础币手续费。此前辅助函数的测试没有覆盖实际命令入口。

现在合并只采用统一的逐币种净变动计算，并测试真正的工具入口。测试包含先买后卖、两笔基础币手续费，核对余额、持仓、原账户资产和按买一价估算的净值；源账本保持不变。

合并前还必须满足：来源属于同一账户和协议、实际查询账户一致、没有未确认订单、预算有明确记录、订单副本没有冲突。所有来源与目标目录加锁后重新读取；迁移从账本创建起就标为未批准，复制中断也不能变成可下单状态。批准和修复流程在持锁后读取状态。

### 订单状态与账户边界

开始提交只接受已有的待提交意图，状态变化与计数一次提交。不存在、已结算、已拒绝或结果不明的意图不能被重新开启。提交前失败只能关闭仍未发送的意图，不能抹掉未知结果。

模拟、Coinbase 和 OKX 现在都使用相同的尝试计数入口。发送前还会比较当前计划与已保存计划。Coinbase 在对账前绑定或验证投资组合；已初始化但未记录身份的旧账本拒绝自动接入另一个账户。

审计去重包含交易所、环境和账户；同一订单的方向、币种、数量或结算不一致会报告冲突。不完整或非法结算不再被跳过。审计在同一个只读数据库快照中读取元数据和订单。

### 历史训练恢复

旧保存记录中的行情游标指向下一根 K 线，虚拟时间却是上一轮时间。恢复时只推进了行情，导致重新使用上一分钟，可能改变冷却检查及成交次数。现在恢复同时推进虚拟时间，并验证连续运行与分段恢复的账务、订单和观察记录一致。

历史训练复用主程序的脑状态与账本提交函数，避免两套保存逻辑继续分化。初始化、恢复和报告写入出错时都释放账本连接；恢复未发送意图的审计记录与状态变化也一起提交。

### 状态文件、监控与构建

部署产生的带摘要状态文件名，旧迁移工具不能识别。现在恢复、部署和迁移共用名称及目录校验，既支持轮换文件，也支持预训练文件；路径不能越出运行目录。复制文件先写入磁盘再更新目标。

健康状态按最新事件判断，旧的成功文件不能覆盖较新的网络失败。查不到订单状态时显示未知。增量日志读取使用文件身份辨认轮换，避免替换后的文件大小相同时漏读。只读数据库路径按 URI 编码，目录中的 `#` 等字符不会截断路径或让程序打开另一个文件。

MSVC 分支原来选择的是 `cl`，却只与 `cl.exe` 比较，因而会使用错误参数；另外补上明确的内核函数导出，并让构建副产物留在数据缓存目录。导出选项依据 [Microsoft 的 /EXPORT 文档](https://learn.microsoft.com/en-us/cpp/build/reference/export-exports-a-function?view=msvc-170)。该分支验证了命令生成，未在本机执行 MSVC 编译。

## 验证与边界

完整连接图校验通过：166,700 个神经元、25,582,938 条有向连接，数组摘要与锁定记录一致。测试使用本地数据和测试替身，没有向交易所提交订单，也没有修复或迁移真实运行账本。

全量测试 482 项通过、0 项失败；末轮修改后补充了针对性回归，合并去重后共 485 项通过、0 项失败，包含完整神经网络检查。运行记录保留在本地忽略目录，4 条第三方依赖弃用提示仍存在。

这些结果验证软件边界和恢复一致性，不证明交易学习有效。每日成交上限仍按订单创建日归属，跨日结算口径未在本次改动中重新定义；监控依据记录推断运行情况，并不是进程存活探针。
