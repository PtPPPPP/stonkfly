# 主程序可维护性审查（2026-09-22）

审查对象是命令入口及运行循环。原 `cli.py` 共 1,012 行，`main()` 单个函数占 921 行，将参数、账户启动、迁移、读行情、神经观察、下单、保存和异常处理放在同一作用域。局部修改需要同时理解大量临时变量和退出路径，是主要维护负担。

## 调整结果

| 文件 | 职责 | 行数 |
| --- | --- | ---: |
| `stonkfly/cli.py` | 定义和校验命令参数，分发命令，显示状态 | 170 |
| `stonkfly/runner.py` | 管理单次运行、启动检查、观察与执行顺序 | 398 |
| `stonkfly/run_state.py` | 保存运行资料、校验协议、输出诊断 | 168 |

合计 736 行，比原主程序减少 276 行，约 27%。入口 `main()` 为 36 行，运行流程中最长的方法为 50 行。减少来自合并重复等待和诊断逻辑、复用账本已有的身份默认值、移除重复说明与参数定义，而不是改变神经网络或交易策略。

`RunSession` 只管理一次运行所需的共享对象。循环明确区分“已提交观察”“等待”“停止”，统一安排下一次等待。资源用 `ExitStack` 统一释放；读取预算用独立的上下文管理器保证异常和提前返回也会清除。没有引入新依赖或额外服务层。

## 发现并修复的问题

- OKX 模拟运行的账户客户端与行情客户端不同，旧代码仅限制了前者。现在二者共享同一观察阶段预算，提交、对账和成交查询仍不受这一预算截断。
- 定时校时旧代码捕获所有异常后继续运行。现在只有明确分类的临时读取故障可以保留上次有效偏移，程序错误和超限偏移直接停止；成功刷新也同步更新本地状态显示。
- 旧清理顺序中，关闭账本出错会跳过释放运行锁。现在即使关闭失败，也执行锁释放。
- 旧等待逻辑两次读时钟可能产生负数休眠时间。现在每轮只计算一次剩余时间。
- 回放速度拒绝 NaN 和无穷大；日志文件状态查询中的权限等错误不再被当成文件不存在。
- 网页默认监听地址的旧测试重新构造了一个独立参数解析器，未验证真实入口。现在直接检查生产解析器。

## 保留的执行边界

观察依次经过：对账、带预算的数据读取、风控和预热检查、神经观察、持久化脑状态与账本、获取新报价、执行原神经提议、记录结果。任何提交结果不确定都停止，不能重试成新订单。只检查启动的命令即使带协议迁移，也不进入观察或交易循环。

神经连接图、可塑性、动作解码、奖励计算、金额精度和订单限制没有修改。历史运行的源码摘要仍然严格校验；重构不会自动接受旧运行目录的协议变化。

使用重构前保存的入口与新入口进行离线对照：实际参数定义一致；在默认奖励与按成交重设参照值两种配置下，使用明确的测试控制器输入，相应账本、订单、观察记录及图像输入校验一致。这是软件行为验证，不是神经网络效果证明。
