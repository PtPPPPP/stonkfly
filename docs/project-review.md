# 项目评估（2026-09-21）

判断：Stonkfly 已具备可运行、可追溯的神经网络交易实验基础，但尚未证明能够通过学习提高交易收益。工程可运行与交易有效是两个不同的验收目标。

## 已确认的优点

- 完整保留目标连接图。此次本地校验确认 166,700 个神经元、25,582,938 条有向连接，编译数组与锁定摘要一致。
- 行情、视觉输入、神经传播、可塑性、固定动作解码和订单执行有独立模块。交易动作来自固定解码，风控只能拒绝，不能替换成另一笔交易。
- 金额使用 Decimal；交易前保存订单意图；不确定的交易结果阻止继续下单；已结算订单具备防重复记账检查。
- 默认模拟交易。OKX 适配器只支持模拟账户，具有持久化尝试次数限制、账户状态核对和异常订单调查工具。
- 终端、网页、账本和脑状态保存使实验可以观察、追踪和恢复；网页默认仅绑定本机。

## 当前缺点与限制

- **学习效果没有验收证据。** 历史回放工具已存在，但没有完成独立时间段、多次独立启动、冻结权重、打乱奖励、现金和持有基准、遗忘及权重重置的统一对照实验。权重改变不能推出收益改善。
- **奖励解释存在局限。** 奖励来自资产净值变化，不能证明最后一个动作造成了变化。按成交重设参照值的模式不会因为卖出后行情上涨就惩罚空仓，也可能重复奖励同一段累计变化，并将即时成交费用移出下一次比较。
- **实验环境与交易环境有差距。** 历史回放主要使用收盘价，模拟成交不覆盖真实盘口深度、排队、流动性和完整冲击成本；输入画法与人为固定解码也会影响行为。
- **维护负担集中。** CLI 同时负责参数、启动、迁移、时钟、观察、执行、保存与异常处理，接近千行；运行历史文档与当前行为已有不一致。此次纠正了每日限制口径和奖励描述，但不将历史报告视为当前验收证明。
- **运行仍依赖本机和外部服务。** 数据集、原生编译器、持续进程和交易所响应都影响可用性；账本锁仅覆盖同一个本地目录，不能隔离不同机器或复制目录中的账户操作。

## 本次审查修复

1. 设置迁移先检查账本环境、计价币和已绑定账户；身份不符时不更新设置。
2. 最新脑状态校验失败时停止，不再将旧脑状态自动配上当前账本。
3. 预训练遇到损坏或不匹配的数据缓存直接停止；已有账本禁止替换数据，包括 `--refresh`。
4. 预训练与部署使用目录锁；部署在读取状态前锁定两端，先持久化独立的脑状态文件，再更新账本引用。
5. 网页并发读取串行更新共享事件游标；修正一个始终为真的超时测试断言。
6. 完整连接图测试明确标记并由 `STONKFLY_FULL_TEST=1` 启用；执行规则测试使用明确的测试替身，避免普通测试依赖本机大数据。
7. 补充数据库、日志和 Windows 编译文件的忽略规则；检查待提交内容与本地凭据没有匹配。

## 验证边界

此次测试不向交易所提交订单。完整图校验、离线集成测试、无本地数据的普通测试和安装包检查用于验证软件行为，不证明实际账户运行或盈利能力。个人凭据、账户资料、运行日志、余额、训练数据和脑状态均不随评估发布。

本地完整测试：438 项通过，0 项失败。另在禁用本地凭据、数据目录不存在的条件下，普通测试 431 项通过，0 项失败，7 项完整图测试按设计跳过。依赖一致性检查、安装包构建、关键静态资源入包检查和暂存内容检查均通过。仍有 4 条第三方依赖弃用提示，不属于测试失败。

普通验证使用 `python -m pytest -q`。准备好完整数据后，设置 `STONKFLY_FULL_TEST=1`、`OPENBLAS_NUM_THREADS=1` 再运行同一命令。详细测试输出保留在本地忽略目录，不作为收益证据发布。
